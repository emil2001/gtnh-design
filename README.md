# GTNH Design

Инструменты для итераций над постройками GT New Horizons: schematic → быстрый набросок → рендер настоящими моделями игры → исправления без перезапуска клиента.

| Режим | Что показывает | Что требуется |
| --- | --- | --- |
| `render_fast.py` | Объём, силуэт и примерные цвета. Все блоки показаны кубами | Python 3.10+, NumPy, Pillow |
| `render_native.py` | Ступени, плиты, ограды, текстуры и TileEntity-модели через Minecraft + Schematica + установленные моды | macOS/APFS, Prism, установленная GTNH 2.9.0-RC-2 с lwjgl3ify/SDL, JDK 21, графическая сессия |

Нативный режим запускает отдельный скрытый клиент. Это не серверный рендер и не полностью headless-процесс: ему нужны OpenGL, графическая сессия и память для сборки. Окно остаётся скрытым, мышь не захватывается. После первого старта один процесс обслуживает следующие итерации.

| Быстрый набросок | Нативный рендер того же стенда |
| --- | --- |
| ![Кубический набросок](docs/fast-preview.png) | ![Настоящие модели игры](docs/native-preview.png) |

Стенд включает ступени, плиты, ограды, стекло, воду, сундук, Chisel, ArchitectureCraft и Carpenter's. [Результаты проверки](docs/verification.md).

## Быстрый старт

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python example_scene.py
python render_fast.py runtime/example.schematic --output runtime/example-draft.png
python schematic.py runtime/example.schematic
python -m unittest -v test_tools
```

`example_scene.py` создаёт синтетический стенд, а не копию пользовательского мира. Быстрый рендер не требует конфига или запуска Minecraft. Для других ракурсов используйте `--azimuth`; параметры доступны через `--help`.

## Нативный рендер

1. Установите GTNH **2.9.0-RC-2** в Prism, войдите в аккаунт Minecraft и один раз успешно запустите сборку. Сборка должна содержать Schematica и её зависимости, ArchitectureCraft, Carpenter's Blocks, Chisel и Et Futurum Requiem для комплектного стенда.
2. Подготовьте отдельное локальное сохранение для предпросмотра. В `preview_world` укажите имя его папки в `saves`, а не отображаемое название. Оно будет скопировано в изолированный экземпляр.
3. Скопируйте `config.example.json` в `config.local.json`. Укажите каталог данных Prism, исполняемый файл Prism, JDK 21, папку исходного экземпляра и сохранения. Все пути локальные; конфиг игнорируется Git. Альтернативный путь к конфигу задаётся через `GTNH_DESIGN_CONFIG`.
4. Выполните:

```sh
python build_native.py
python render_native.py runtime/example.schematic --id example-native
python worker.py status
```

Результат: `runtime/renders/example-native/`, шесть PNG и `result.json`. Новый запуск команды с другим `--id` перечитает schematic, даже если путь к нему тот же. Повторно использовать существующий ID нельзя. Пример размера кадра: `--width 1920 --height 1200`.

Успех означает `status=complete`, `gl_error=0`, пустой `renderer_messages`, ожидаемые размеры и число TileEntities. Просмотрите сами PNG: успешный импорт не подтверждает качество дизайна.

При первом создании экземпляра Prism иногда не замечает новую папку, пока открыт. Если Java не стартует, закройте и снова запустите **Prism**, затем повторите команду. Обычные изменения schematic перезапуска не требуют.

```sh
python verify_native.py     # реальный стенд: ошибка импорта, recovery, две итерации, один PID
python worker.py stop       # штатное завершение скрытого клиента
```

`verify_native.py` пишет локальный `runtime/verification.json`. Первый старт может занимать несколько минут. Не изменяйте подключённые моды/ресурсы во время работы: они связаны с исходной установкой. Конфиги и сохранение изолированы APFS-копиями; исходное сохранение не используется как рабочее. Игровые сохранения могут содержать личные данные — выбирайте локальный тестовый мир.

Экземпляр worker привязан к пути клона и исходной установки. Если перемещаете toolkit или используете второй клон, выберите другое `worker_instance` либо пересоздайте старый тестовый экземпляр после его штатной остановки. Большое исходное сохранение может долго проходить первичное сканирование VisualProspecting; небольшой тестовый мир запускается быстрее.

`--interactive` подключает renderer к исходному видимому экземпляру Prism. Это запасной режим для диагностики; штатный автономный цикл использует отдельный скрытый экземпляр.

## Рельеф и формат

Читайте **локальную копию** нужного мира, чтобы увидеть постройку на настоящем рельефе:

```sh
python world_crop.py --world /absolute/path/to/world-copy \
  --bounds 0 60 0 31 100 31 --dimension 0 \
  --output projects/terrain.schematic
```

Границы включительные, порядок `X0 Y0 Z0 X1 Y1 Z1`. Источник открывается только на чтение; выходной файл внутри исходного сохранения запрещён. Отсутствующие чанки вызывают ошибку. Для Nether/End используются `--dimension -1` / `1` и каталоги `DIM-1` / `DIM1`.

В Python массивы блоков имеют порядок **Y,Z,X**. `schematic.write()` сохраняет именованную палитру `SchematicaMapping`, metadata, typed TileEntity NBT и `WEOrigin`. Высокие серверные ID разрешаются по именам, а локальная палитра Alpha ограничена 4096 значениями. Не подставляйте числовые ID из другого мира. Для старого Alpha без имён `render_fast.py` / `schematic.py` требуют `--registry` с JSON вида `{"0":"minecraft:air","1":"minecraft:stone"}`.

`GTNHPreviewMultipart` сохраняет multipart-данные для этого renderer. Исходные metadata >255 остаются в `GTNHPreviewMetadata` для аудита, но рендер использует младший байт: такой контекст нельзя считать точным для затронутых блоков. Эти расширения не являются универсальным форматом вставки.

Рендер не размещает schematic в мире. Schematica Printer не воспроизводит произвольный TileEntity NBT, поэтому ArchitectureCraft может превратиться в одинаковые колонны. Перед вставкой отдельно проверьте поддержку NBT, ориентации и высоких GTNH ID выбранным редактором. Обычный WorldEdit 6.1.1 ограничен 12-битными ID; не обещайте им безопасную вставку всей GTNH-палитры.

## Скилл для агента

Скилл находится в [`skills/gtnh-design/SKILL.md`](skills/gtnh-design/SKILL.md). Для Codex можно установить его ссылкой на клон:

```sh
mkdir -p ~/.codex/skills
ln -s /absolute/path/to/gtnh-design/skills/gtnh-design ~/.codex/skills/gtnh-design
```

Если скилл скопирован отдельно, задайте `GTNH_DESIGN_ROOT` как путь к клону. Он ведёт агента через набросок, точный рендер, осмотр изображений и исправления, сохраняя NBT и координаты настоящего рельефа.

## Что хранится в Git

Исходники Python/Java, конфиг-пример, зависимости, проверки и скилл. Модпак, игровые JAR/текстуры, JDK, аккаунты Prism, миры, schematic проектов, логи и локальные пути в репозиторий не входят. Рабочие данные находятся в игнорируемых `runtime/` и `projects/`.

Проверенная платформа нативного режима — macOS/APFS с указанной версией GTNH. Другие версии, Linux/Windows, шейдеры и полный каталог модовых блоков не проверены. Обычные игровые Entities не входят в рендер; поддержка конкретной модели зависит от установленного модового renderer.
